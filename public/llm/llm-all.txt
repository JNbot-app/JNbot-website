# JNbot Plugin Authoring Reference

# JNbot plugin authoring

Create or update plugins with `save_plugin`; do not merely return source code when the user asked for a plugin. Read this guide first and use `get_jnbot_reference` with the relevant section for an API you are unsure about.

## Entrypoints

Normal plugins own their bot lifecycle. Import `script` and read persistent options from `script.settings`.

```js
const { script } = require('jnbot');

async function main() {
  for await (const bot of script.forEachBot(script.getAlts(), script.settings)) {
    bot.chat(script.settings.message);
  }
}

main();
```

Actions run on one already-connected bot. They must define `async function main(bot, settings, args = [])`; never join another bot in an action. `settings` is the saved option object plus run-time overrides. `args` is transient positional input only.

```js
async function main(bot, settings, args = []) {
  bot.chat(settings.message);
  return { sent: settings.message, args };
}
```

## Options

Add an option for any value a user may want to change without editing code. Read it as `script.settings.optionId` in normal plugins or `settings.optionId` in actions. Schemas are arrays of named sections. Every option needs a stable URL-safe `id`, a label, and a type. Never set defaults for passwords, tokens, credentials, or API keys.

| Type | Stored value | Required configuration |
| --- | --- | --- |
| `input` | string or number | `inputType` may be `text`, `number`, or `password` |
| `switch` | boolean | none |
| `select` | string or number | non-empty `{ label, value }[]` `options` |
| `multiSelect` | string array | non-empty string `options` |
| `slider` | number | `min`, `max`, positive `step` |
| `gamemodeSelect` | string or string array | optional `multiple` |
| `altSelect` / `altsSelect` | alt name / alt-name array | none |
| `tagsSelect` | tag-ID array | none |
| `altRange` | `[start|null, end|null]` | none |
| `list` | object array | 1–6 unique `fields` |
| `coordinate` | `{ x?, y?, z?, dimension? }` | optional `withDimension` |
| `keybind` | string | optional `simple` |

```json
[
  {
    "name": "General",
    "options": [
      { "id": "message", "label": "Message", "type": "input", "defaultValue": "Hello" },
      { "id": "repeat", "label": "Repeat", "type": "slider", "min": 1, "max": 10, "step": 1, "defaultValue": 1 },
      { "id": "enabled", "label": "Enabled", "type": "switch", "defaultValue": true }
    ]
  }
]
```

Use `valueByFieldId` only to make an eligible `select`, `gamemodeSelect`, `altSelect`, or `keybind` option control how another option is stored.


## Save workflow

1. Determine whether the request is a normal plugin or an action.
2. Create the source and an option schema together when settings are needed.
3. Call `save_plugin` with `mode: "source"`; include `pluginId` only when updating.
4. Poll `get_operation` rather than resubmitting a pending save.
5. Report the installed plugin ID or the actionable validation/approval result.



## Preferred APIs

Local AI is available through `script.ai`. Create an agent with explicit tool names, descriptions, object JSON Schemas, and optional handlers. `predict()` returns proposed calls without executing them. `run()` makes one prediction and executes its accepted calls sequentially, retaining completed results if a later handler fails. Handler results are not sent back to the model. Each input is independent; unchanged tools stay prepared. Agents start with no tools and support `setTools`, `addTool`, `removeTool`, and `dispose`.

Choose `model: 'main'` for accuracy or `model: 'flash'` for lower memory use and faster inference. Main is the default. Both support tool calls and `script.ai.extract(text, schema, options)`, which returns a validated object or `null`. Reasoning is disabled by default. Pass `{ reasoning: true }` to `agent.predict()`, `agent.run()`, or `script.ai.extract()` to generate reasoning before tool calls. Pass `false` or omit the option to skip reasoning; predictions then return `reasoning: null`. `agent.embed(text, options)` returns `{ modelId, values }` using the agent's selected Gemma model, including its custom model URL. It accepts `signal` and `timeoutMs`, works without tools, and cancels when the agent is disposed. `script.ai.embed(text, options)` also remains available. Both embedding methods reject flash with `AI_UNSUPPORTED_FEATURE`. Rebuild stored embeddings when the model ID changes.

Tool filtering is disabled by default. On main, pass `{ toolFilterThreshold: 0.75 }` to `agent.predict()`, `agent.run()`, or `script.ai.extract()` to retain only tools whose name and description meet that cosine threshold. Values must be finite and between -1 and 1. Omit it or pass `null` to disable it; flash bypasses filtering. Tool vectors are cached in the inference worker, and the query encoding is shared with memory. When no tools survive, inference returns no match without decoding. Calibrate the threshold on your messages: similarity alone does not reliably distinguish placing from breaking, selling from buying, negation, or exact prices. The value 0.75 is an example, not a recommended default.

Pass `modelUrl` to `createAgent({ tools, model, modelUrl })`, `extract(text, schema, { model, modelUrl })`, or `embed(text, { model: 'main', modelUrl })` to use a custom model. The URL must download an HTTPS `.cact` file compatible with the selected variant. Omit it or pass a blank string to use the configured release model. An agent keeps its selected variant and URL. Downloads happen at first inference; creation and tool edits do not load a model. Installed files work offline, and flash can reuse a compatible installed main file. Publish new custom model versions at new URLs. Download or loading failures report an error without substituting another model. AI-authored plugins with external network access disabled cannot select custom models.

The model focuses on English. All supplied tools must fit within the model context; registration has no fixed tool count limit. Optional fields can be absent, and confidence can be `null`. Supported schema keywords are the fields of `AiSchema`; unsupported keywords fail at registration. Requests default to a 120-second deadline and 512 output tokens. Options accept `signal`, `timeoutMs`, and `maxNewTokens` where applicable. `run()` has no completion loop or step limit. A running handler cannot recursively call AI. Existing plugin permissions still apply to handlers.

Native support must be packaged for the device. Local inference supports desktop builds, Android ARM64, and iOS device and simulator builds. Other Android architectures return `AI_UNSUPPORTED_PLATFORM`. The app command UI and typing previews are not part of this API.

- Use `script.forEachBot(script.getAlts(), script.settings)` for multi-alt scripts; its settings object enables standard alt filters.
- Use `await bot.openWindow(command)` rather than sending a command then waiting for a window event.
- Use `bot.findWindowSlots()` before relying on slot numbers and `await bot.transferItems()` for supported transfer flows.
- Import JNbot helpers from `require('jnbot')`. Supported sandbox modules include `axios`, `events`, selected Prismarine modules, `vec3`, and `assert`; AI-authored plugins cannot use process, child processes, proxy APIs, account passwords, Fabric clients, or managed servers.
- [IMPORTANT] Use `BotMachine` for the entire bot task. Avoid creating long functions. Split the task up into smaller steps. This will allow the bot to recover from errors like if some action failed or the bot gets suddenly kicked to hub, BotMachine allows you to deal with these scenarios much easier. For the `when` condition, try to find when the bot should perform the action. For example, if the bot doesn\'t have a window opened -> do window action. Or if specific window must be opened, we can check it using bot.getWindowTitle(). Avoid doing stuff like state.step = "step1" and then checking for state.step === "step1" in the next task.

# Compact plugin examples

## Local tool calls and extraction

```js
const { script } = require('jnbot');

async function main() {
  const schema = {
    type: 'object',
    properties: { quantity: { type: 'integer', minimum: 1 } },
    required: ['quantity'],
    additionalProperties: false,
  };
  // Use an HTTPS URL for a compatible fine-tuned .cact model, or leave blank.
  const modelUrl = '';
  const agent = script.ai.createAgent({ model: 'flash', modelUrl });
  agent.addTool({
    name: 'set_quantity',
    description: 'Set the requested item quantity',
    parameters: schema,
    handler: ({ quantity }) => {
      console.log(`Requested quantity: ${quantity}`);
      return { quantity };
    },
  });
  try {
    console.log(await agent.predict('Set quantity to 7')); // No handler runs.
    const result = await agent.run('Set quantity to 7');
    if (result.status === 'failed') console.log(result.error, result.results);
    console.log(await script.ai.extract('The quantity is 3', schema, { model: 'flash', modelUrl }));
    const { modelId, values } = await script.ai.embed('diamond sword', { model: 'main' });
    console.log(modelId, values.length);
    agent.removeTool('set_quantity');
    agent.setTools([]);
  } finally {
    agent.dispose();
  }
}
```

## Learned mob fighter (Brain)

Record yourself fighting in the JNbot Client, train, then let a bot copy you. Recordings store raw observations, so you can change `features` and train again without recording again.

```json
[{"name":"Brain","options":[{"id":"mode","label":"Mode","type":"select","options":[{"label":"Record (JNbot Client)","value":"record"},{"label":"Train","value":"train"},{"label":"Run on bot","value":"run"}],"defaultValue":"record"},{"id":"minutes","label":"Record minutes","type":"input","inputType":"number","defaultValue":"10"}]}]
```

```js
const { Brain, script } = require('jnbot');

const brain = new Brain({
  name: 'mob-fighter',
  features: (o) => ({
    health: o.self.health,
    onGround: o.self.onGround,
    mobs: Brain.swarm(o, { filter: (e) => e.hostile }),
    terrain: Brain.rays(o, { count: 8, length: 4 }),
  }),
  // which mob to focus: learned from the mob you attack next. The bot walks to it
  // with the pathfinder (around walls) and copies you once it's in reach and in
  // sight; every head also sees its features as `target.*`
  target: {
    candidates: (o) => o.entities.filter((e) => e.hostile),
    features: (o, e) => ({ dist: e.dist, angle: e.angle, dy: e.dy, approach: e.approach, health: e.health }),
  },
  heads: ['forward', 'strafe', 'jump', 'sprint', 'attack'],
});

async function main() {
  const { mode } = script.settings;
  if (mode === 'record') {
    const [client] = await script.getMcClients();
    if (!client) return console.log('Launch Minecraft with the JNbot Client first');
    const recording = await brain.record(script.getMcClient(client.clientId));
    script.onExit(() => recording.stop());
    const total = Number(script.settings.minutes) * 60;
    for (let seconds = 0; seconds < total; seconds++) {
      script.updateProgress({ current: seconds, total });
      await new Promise((resolve) => setTimeout(resolve, 1000));
    }
    await recording.stop();
  } else if (mode === 'train') {
    console.log(await brain.train());
  } else {
    for await (const bot of script.forEachBot(script.getAlts().slice(0, 1), {})) {
      script.onExit(brain.run(bot));
      await new Promise(() => {}); // run until the plugin is stopped
    }
  }
}

main();
```

### Learned farmer (block targets)

Targets can be blocks too: `o.findBlocks(match)` lists blocks in the observed cube with their state (e.g. wheat `age`). The bot learns which block you break or right-click next, walks there, and then `attack` breaks it and `use` right-clicks it (planting seeds on farmland). Full plugin: `examples/brain/farm-bot.js`.

```js
const ripe = (b) => b.name === 'wheat' && b.state?.age === 7;
const brain = new Brain({
  name: 'farm-bot',
  observe: { blockRadius: 8 }, // see across the field
  features: (o) => ({ ripe: o.findBlocks(ripe).length, seeds: o.self.items.wheat_seeds ?? 0 }),
  target: {
    // all wheat (so it learns to wait for age 7) and empty farmland to replant
    candidates: (o) => o.findBlocks((b, dx, dy, dz) =>
      b.name === 'wheat' || (b.name === 'farmland' && o.block(dx, dy + 1, dz)?.name === 'air')),
    features: (o, b) => ({ wheat: b.name === 'wheat', age: b.state?.age, dist: b.dist, angle: b.angle }),
  },
  heads: ['forward', 'strafe', 'jump', 'attack', 'use', Brain.hold({ seeds: /wheat_seeds/ })],
});
```

/**
 * Shared types for the transparent JNbot proxy (proxyV3).
 *
 * This file is the canonical home for the recording format and the IPC shapes
 * exchanged with the renderer. The UI imports `RecordingHeader` / `ProxyInfo`
 * from here.
 */

/** Direction of a packet relative to the player. */
type PacketDirection = 'c2s' | 's2c';

/** Packet data decoded by minecraft-protocol for the current client version. */
type ProxyPacketData = Record<string, unknown>;

/** A raw, decompressed Minecraft packet body. It includes the packet id. */
type RawPacket = Uint8Array;

/** A parsed packet queued after the current packet. */
interface InjectedPacket {
  kind: 'parsed';
  name: string;
  data: ProxyPacketData;
}

/** A raw packet queued after the current packet. */
interface InjectedRawPacket {
  kind: 'raw';
  raw: RawPacket;
}

type InjectedProxyPacket = InjectedPacket | InjectedRawPacket;

interface PacketContext<T extends ProxyPacketData | null = ProxyPacketData | null> {
  readonly name: string;
  readonly state: string;
  readonly direction: PacketDirection;
  /** The decompressed packet body JNbot will forward, including its packet id. */
  readonly raw: RawPacket;
  /** True when JNbot could not decode this packet for the active protocol. */
  readonly unparsed: boolean;
  readonly isFromServer: boolean;
  data: T;
  readonly isModified: boolean;
  readonly isDropped: boolean;
  readonly injected: readonly InjectedProxyPacket[];
  /** Mark in-place edits to `data` for re-encoding. */
  markModified(): this;
  /** Replace this packet with a raw packet body. Works for undecodable packets. */
  replaceRaw(raw: RawPacket): this;
  /** Stop forwarding this packet. */
  drop(): this;
  /** Send a parsed packet to the same target after this packet. */
  inject(name: string, data: ProxyPacketData): this;
  /** Send a raw packet body to the same target after this packet. */
  injectRaw(raw: RawPacket): this;
}

type PacketHandler = (context: PacketContext) => void;

interface PacketPipeline {
  on(events: string | string[], handler: PacketHandler): this;
  once(events: string | string[], handler: PacketHandler): this;
  off(events: string | string[], handler: PacketHandler): this;
  clear(): void;
}

/** Read-only connection details for either side of a proxy connection. */
interface ProxyEndpoint {
  readonly username: string;
  readonly uuid: string;
  readonly version: string;
  readonly state: string;
}

interface Connection {
  readonly client: ProxyEndpoint;
  bridge: ProxyEndpoint | null;
  readonly username: string;
  readonly uuid: string;
  readonly config: ProxyServerConfig;
  readonly pipeline: PacketPipeline;
  readonly pluginManager: PluginManager;
  readonly isReady: boolean;
  tell(message: string): void;
  /** Write a decoded packet toward the server (`c2s`) or client (`s2c`). */
  write(direction: PacketDirection, name: string, data: ProxyPacketData): boolean;
  /** Write a raw, decompressed packet body toward the server or client. */
  writeRaw(direction: PacketDirection, raw: RawPacket): boolean;
  end(reason?: string): void;
  close(): void;
  on(event: 'close', listener: (connection: Connection) => void): this;
}

/**
 * What a recording is for:
 * - `replay`: client->server stream, used to drive a connection (the default).
 * - `debug`: both directions, large packets truncated — for inspection only.
 * Absent on legacy recordings (treat as `replay`).
 */
type RecordingKind = 'replay' | 'debug';

/** Metadata file written alongside every recording (`<name>.json`). */
interface RecordingHeader {
  /** stable id == base filename; survives renames of the display `name` */
  id: string;
  name: string;
  /** what the recording is for; absent on legacy recordings (treat as 'replay') */
  kind?: RecordingKind;
  /** recorder format version */
  version: string;
  timestamp: number;
  /** minecraft version the recording was captured on */
  mcVersion: string;
  ignoredPackets: string[];
  packetCount: number;
  /** total duration in ms */
  duration: number;
}

/** One line of the NDJSON `<name>.log` data file. */
interface RecordingPacket {
  /** packet name */
  n: string;
  /** delta time from recording start, ms */
  dt: number;
  /** packet params */
  p: Record<string, any>;
  /** free-form metadata */
  m: Record<string, any>;
  /** direction; absent on legacy recordings (treat as 'c2s') */
  d?: PacketDirection;
}

/** A pure transform applied to a packet during record or replay. */
type Transformer = (packet: RecordingPacket) => RecordingPacket | null;

/**
 * A cooldown owned by your plugin. Returned by `script.getCooldowns()` and
 * `script.addCooldown()`. Use the methods to inspect or restart its countdown.
 */
interface Cooldown {
  readonly id: string;
  /** Owning plugin (set automatically). `pluginId + reminderId` is globally unique. */
  readonly pluginId: string;
  /** Plugin-defined id (e.g. the gamemode). Unique within a pluginId. */
  reminderId?: string;
  name: string;
  /** Cooldown length in milliseconds. */
  cooldown: number;
  /** Start epoch (ms); the cooldown is ready at `time + cooldown`. */
  time: number;
  /** Option overrides replayed when this cooldown auto-runs the plugin. */
  options?: Record<string, any>;
  /** Epoch (ms) at which this cooldown becomes ready (`time + cooldown`). */
  readonly readyAt: number;
  /** `true` once the cooldown has fully elapsed. */
  isCompleted(): boolean;
  /** Milliseconds left until the cooldown is ready (0 once completed). */
  remaining(): number;
  /** Restart the countdown from now (ready again after one cooldown). */
  reset(): Promise<Cooldown>;
  /** Permanently remove this cooldown. */
  delete(): Promise<void>;
}

interface TaskContext<S extends object = Record<string, unknown>> {
  /** The bot. */
  bot: Bot;
  /** Shared, mutable state for this run — persists across ticks. */
  state: S;
  /** The machine itself, so a task can pause/stop/setDelay/addTask, etc. */
  machine: BotMachine<S>;
}

type Guard<S extends object = Record<string, unknown>> = (
  ctx: TaskContext<S>,
) => boolean;

type Action<S extends object = Record<string, unknown>> = (
  ctx: TaskContext<S>,
) => Awaitable<void>;

interface Task<S extends object = Record<string, unknown>> {
  /** Optional label, logged (when `debug`) each time the task runs. */
  name?: string;
  /** Task runs only when this returns true AND no earlier task matched. */
  when: Guard<S>;
  /** What to do when this task is the first match of the tick. */
  run: Action<S>;
  /** Run at most once (re-armed on rejoin when `resetOnceOnRejoin`). */
  once?: boolean;
  /** Internal: set once a `once` task has fired. */
  _done?: boolean;
}

// ─── Brain API ───────────────────────────────────────────────────────────

// Learned bot behaviour ("brains"): record a player in the JNbot Client, train
// small gradient-boosted tree models, and run them on a mineflayer bot.
// Same authoring rules as pluginApi.d.ts: single-line imports, export-only.


interface BrainBlock {
  name: string;
  solid: boolean;
  liquid: boolean;
  /** block properties, e.g. `{ age: 7 }` for fully grown wheat; undefined when it has none */
  state?: Record<string, string | number | boolean>;
}

/** A block found with {@link BrainObservation.findBlocks}, usable as a target. */
interface BrainBlockTarget extends BrainBlock {
  kind: 'block';
  /** world position as 'x,y,z' */
  id: string;
  /** world block position */
  x: number; y: number; z: number;
  /** offset from your feet block, for `o.block(dx, dy + 1, dz)` (what's above it) */
  dx: number; dy: number; dz: number;
  /** distance to the block centre */
  dist: number;
  /** offset in your facing frame: blocks in front of / to the right of you */
  forward: number;
  right: number;
  /** horizontal angle from your crosshair in radians, positive = to the right */
  angle: number;
}

interface BrainEntity {
  kind: 'entity';
  id: number;
  /** short entity type, e.g. 'zombie', 'player' */
  type: string;
  player: boolean;
  hostile: boolean;
  x: number; y: number; z: number;
  /** velocity in blocks/tick */
  vx: number; vy: number; vz: number;
  yaw: number;
  /** NaN when unknown */
  health: number;
  /** held item name, '' when empty */
  held: string;
  dist: number;
  /** height difference (entity - you) */
  dy: number;
  /** offset in your facing frame: blocks in front of / to the right of you */
  forward: number;
  right: number;
  /** horizontal angle from your crosshair in radians, positive = to the right */
  angle: number;
  /** speed toward you in blocks/tick */
  approach: number;
  /** arrow, trident, fireball, snowball, … */
  projectile: boolean;
  /** how far its current path passes from your body (blocks); with closestIn > 0 and a small value, it's coming at you */
  closest: number;
  /** ticks until it is closest to you; negative when moving away, NaN when not moving */
  closestIn: number;
  /** angle between where it faces and you, radians: 0 = looking straight at you */
  facingMe: number;
  /** ticks since it last shot a projectile, NaN when never seen (a skeleton draws its bow ~20-40 ticks after a shot) */
  sinceShot: number;
}

interface BrainSelf {
  x: number; y: number; z: number;
  vx: number; vy: number; vz: number;
  /** radians, mineflayer convention */
  yaw: number;
  pitch: number;
  health: number;
  food: number;
  onGround: boolean;
  sprinting: boolean;
  sneaking: boolean;
  usingItem: boolean;
  held: string;
  offHand: string;
  /** ticks the current item use has lasted (bow charge, eating, blocking); 0 when not using */
  useTicks: number;
  /** inventory item counts by name, e.g. `items.arrow` */
  items: Record<string, number>;
}

/** What the brain sees each step. Identical when recording and when running. */
interface BrainObservation {
  /** ms timestamp */
  t: number;
  self: BrainSelf;
  /** nearby entities, nearest first */
  entities: BrainEntity[];
  /** block at an offset (world axes) from your feet block; undefined outside the observed cube */
  block(dx: number, dy: number, dz: number): BrainBlock | undefined;
  /**
   * Blocks in the observed cube that match, nearest first, e.g. fully grown wheat:
   * `o.findBlocks((b) => b.name === 'wheat' && b.state?.age === 7)`. dx/dy/dz are offsets from your feet block.
   */
  findBlocks(match: (block: BrainBlock, dx: number, dy: number, dz: number) => boolean): BrainBlockTarget[];
}

/** Something to focus: an entity, or a block from {@link BrainObservation.findBlocks}. */
type BrainTarget = BrainEntity | BrainBlockTarget;

/** What the player did during one step (recorded from the JNbot Client). */
interface BrainInput {
  /** 1 = forward, -1 = back, 0 = none */
  forward: number;
  /** 1 = right, -1 = left, 0 = none */
  strafe: number;
  jump: boolean;
  sprint: boolean;
  sneak: boolean;
  /** entity id or block id ('x,y,z') attacked / broken now or within the next 0.5 s (when training); -1 when unknown; null when none */
  attack: number | string | null;
  use: boolean;
  /** entity id or block id right-clicked now or within the next 0.5 s (when training); -1 when unknown; null when none */
  useOn: number | string | null;
}

/** Feature values; nested objects are flattened to `a.b`, booleans become 0/1. */
type BrainFeatures = { [name: string]: number | boolean | null | undefined | BrainFeatures };

/** A learned decision. Built-in heads use the same shape. */
interface BrainHead {
  name: string;
  /** 'class' predicts one of `classes` (0-based), 'binary' a yes/no, 'value' a number */
  type: 'class' | 'binary' | 'value';
  classes?: number;
  /** label for a recorded step; null skips the step */
  label(input: BrainInput, o: BrainObservation, next: BrainObservation): number | null;
  /** execute the predicted value on the bot */
  apply(bot: Bot, value: number, decision: BrainDecision): void;
  /** controls movement: paused while the bot walks to its target (see {@link BrainRunOptions.navigate}) */
  move?: boolean;
  /** fire a binary head only above this probability, instead of sampling */
  threshold?: number;
  /**
   * Pick randomly by probability (default: the brain's `sample`); false = most likely.
   * A function decides per step, e.g. sample starting an action but not stopping it.
   */
  sample?: boolean | ((o: BrainObservation) => boolean);
}

/** Item name test for {@link BrainConstructor.hold}. */
type BrainHoldCategory = RegExp | ((itemName: string) => boolean);

type BrainHeadName = 'forward' | 'strafe' | 'jump' | 'sprint' | 'sneak' | 'attack' | 'use' | 'turn';

interface BrainObserveOptions {
  /** entities further away are ignored (default 16) */
  entityRadius?: number;
  /** horizontal radius of the observed block cube (default 4); raise it to find target blocks further away */
  blockRadius?: number;
  /** vertical radius of the observed block cube (default 2) */
  blockHeight?: number;
}

interface BrainTrainOptions {
  /** max boosting rounds (default 300) */
  rounds?: number;
  learningRate?: number;
  maxDepth?: number;
  /** min recorded steps per leaf (default 20) */
  minLeaf?: number;
  /** rounds without validation improvement before stopping (default 30) */
  earlyStop?: number;
  /**
   * weight rare actions up so the trees learn when they happen: 0 = off,
   * 1 = fully balanced (default 0.5). Predicted probabilities stay calibrated,
   * so the bot still does them about as often as you did.
   */
  balance?: number;
}

interface BrainOptions<T extends BrainTarget = BrainTarget> {
  /** storage name; recordings and the model live under it */
  name: string;
  /** decision interval in ms (default 100 = 2 ticks) */
  stepMs?: number;
  observe?: BrainObserveOptions;
  /** fixed-size features of the situation */
  features(o: BrainObservation): BrainFeatures;
  /**
   * Learn what to focus: which mob to fight, which crop to harvest. Candidates
   * are entities and/or blocks (`o.findBlocks`); each is scored on its own, so
   * their number and order don't matter. Labelled in hindsight: each step's
   * target is what the player attacks, breaks, right-clicks or aims at within
   * the next 5 s, so steps where they engage nothing teach "no target". Every
   * head also sees the target's features as `target.*` (missing when there is
   * none), e.g. to pick a bow for a mob that is high up. `attack` breaks a
   * target block, `use` right-clicks it (e.g. plants seeds on farmland).
   */
  target?: {
    candidates(o: BrainObservation): T[];
    features(o: BrainObservation, target: T): BrainFeatures;
    /** minimum score (0-1, the chance the player would engage it) to choose a target at all (default 0.3) */
    minScore?: number;
  };
  /** decisions to learn (default: forward, strafe, jump, sprint, attack) */
  heads?: (BrainHeadName | BrainHead)[];
  /**
   * Pick actions randomly by their predicted probability, like the player did
   * (default true). false always takes the most likely action, which never
   * picks actions the player only did sometimes (e.g. strafing).
   */
  sample?: boolean;
  train?: BrainTrainOptions;
}

interface BrainDecision {
  /** predicted value per head: class index (forward/strafe: 0 = back/left, 1 = none, 2 = forward/right), 0/1 for binary */
  values: Record<string, number>;
  /** chosen target, when `target` is configured and a candidate scores high enough */
  target: BrainTarget | null;
  /** while running: the bot is walking to the target and the learned movement heads are paused */
  navigating?: boolean;
}

interface BrainRecording {
  readonly file: string;
  /** recorded steps so far */
  readonly steps: number;
  stop(): Promise<void>;
}

interface BrainHeadReport {
  rows: number;
  rounds: number;
  trainLoss: number;
  validLoss: number;
  /** validation balanced accuracy (mean per-class recall) for class/binary heads */
  accuracy?: number;
  /** most useful features, best first */
  topFeatures: string[];
}

interface BrainReport {
  recordings: number;
  steps: number;
  heads: Record<string, BrainHeadReport>;
  /** how close the player usually was when engaging a target; the learned heads take over within it */
  range?: number;
}

interface BrainRunOptions {
  /**
   * How to aim: 'target' looks at the chosen target (default when `target` is
   * configured), 'turn' uses the learned turn head, false leaves aiming to you.
   */
  look?: 'target' | 'turn' | false;
  /**
   * Walk to the target with the pathfinder plugin (around walls, up stairs) and
   * let the learned heads act once it is within `range` and in sight (default
   * true when `target` is configured). Targets that can't be reached, or that
   * see no progress (getting closer or being hit) for `giveUp` seconds (default 5, 0 = never), are
   * ignored for 10 s. false = the learned heads always move the bot (e.g. parkour).
   */
  navigate?: boolean | { range?: number; giveUp?: number };
  /** called every step after the decision is applied */
  onStep?(o: BrainObservation, decision: BrainDecision): void;
}

interface Brain {
  readonly name: string;
  /** Record the player of a JNbot Client until `stop()` is called. */
  record(client: IMcClient): Promise<BrainRecording>;
  /** Train on all recordings of this brain and save the model. */
  train(options?: BrainTrainOptions): Promise<BrainReport>;
  /** Decide from an observation (loads the saved model on first use). */
  decide(o: BrainObservation): BrainDecision;
  /** Control a bot with the trained model. Returns a stop function. */
  run(bot: Bot, options?: BrainRunOptions): () => void;
  /** Delete all recordings and the model of this brain. */
  reset(): void;
}

interface BrainConstructor {
  new <T extends BrainTarget = BrainTarget>(options: BrainOptions<T>): Brain;
  /** Threat summary of a set of entities in direction sectors around you (fixed size, order-free). */
  swarm(o: BrainObservation, options?: { filter?: (e: BrainEntity) => boolean; sectors?: number; rings?: number[] }): BrainFeatures;
  /** Distance to walls, drops and hazards along rays around you, in your facing frame. */
  rays(o: BrainObservation, options?: { count?: number; length?: number }): BrainFeatures;
  /**
   * Head that learns which item to hold, e.g. `Brain.hold({ sword: /sword/, bow: /bow/, food: /bread|beef/ })`.
   * Value 0 = something else (hand left alone), then one per category in order. Switches via the hotbar.
   */
  hold(categories: Record<string, BrainHoldCategory>): BrainHead;
}

[IMPORTANT] Use `BotMachine` for the entire bot task. Avoid creating long functions. Split the task up into smaller steps. This will allow the bot to recover from errors like if some action failed or the bot gets suddenly kicked to hub, BotMachine allows you to deal with these scenarios much easier. For the `when` condition, try to find when the bot should perform the action. For example, if the bot doesn't have a window opened -> do window action. Or if specific window must be opened, we can check it using bot.getWindowTitle(). Avoid doing stuff like state.step = "step1" and then checking for state.step === "step1" in the next task.
